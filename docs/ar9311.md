# AR9311 / P1 Air backend

`make BACKEND=ar9311 CROSS_COMPILE=... ARLIBRE=...` builds the Linux V4L2
backend without HiSilicon SDK libraries. `BACKEND=hisilicon` remains the default.
Objects are separated by backend; the output executable is `kestrel-air`.

The AR9311 backend requires fpvOS's source SC231AI, CSI, VIF, ISP, CVISP and
Wave5 encoder drivers. The OS loads the modules and supplies board tuning.
Kestrel discovers video nodes by name, exports three-plane YUV420M capture
buffers as DMA-BUFs, and keeps them owned by the encoder until its OUTPUT queue
returns them. Only compressed HEVC bytes are copied into Kestrel's existing
packet ring. Radio framing and ar_libre transport are shared with the Lite.

The initial mode is 1920x1080 at 60 fps, complete-frame HEVC with periodic IDRs.
Runtime bitrate and keyframe requests use V4L2 controls. Slice output, intra
refresh, arbitrary resolutions, rotation, remote ISP tuning, recording, FC UART,
button/LED wiring and P1 temperature/battery telemetry are not implemented.
No HiSilicon MMIO or project-specific radio GPIO/ADC commands are used on P1.
Unassigned vendor board/sensor IDs are reported as zero; the model name identifies P1.

Run through fpvOS's `kestrel-air-run` launcher. It loads source camera drivers,
locks capture against the recorder, and provides:

- `KA_CAMERA_TUNING`: extracted, verified AE tuning file.
- `KA_WB_ORDER`, `KA_WB_RED`, `KA_WB_BLUE`: board-validated ISP statistics order
  and initial Q8 gains.
- `KA_CONFIG` and `KA_PEER_CONFIG`: writable application and paired receiver
  settings. P1 uses `/var/lib/kestrel-air`, separate from factory calibration.

Kestrel starts the source `ar9311-aed` and `ar9311-awbd` after eight capture
frames and stops its children when capture stops. A failed controller or stalled
capture causes a visible application failure, rather than silently streaming
with dead automatic controls.

Provision this unit's radio configuration and saved peer before starting. The
stock JSON on disk can contain DEV-role defaults that its application changes
at runtime; do not feed it unchanged to AP Open8030. Preserve this unit's power
calibration and use native arlink framing, not the stock P1 SDIO block trailer.
The peer settings contain `bb_mac_addr_0` as four integer bytes. Missing settings
must not overwrite calibrated power offsets with Lite defaults.

`make test` checks the shared protocol helpers. `make test-ar9311` verifies that
a stale Lite board setting cannot activate its hardware controls on P1.
Hardware acceptance additionally requires a cold boot, radio association,
received HEVC validation and stop/restart testing; compilation alone is not it.
